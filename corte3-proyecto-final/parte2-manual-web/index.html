Guia practica para elegir estructuras de datos

Este manual resume los temas trabajados durante el semestre y los conecta con el sistema de turnos desarrollado en la Parte 1. Su objetivo es explicar cuando usar arrays, listas, pilas, colas, hash, arboles, AVL y grafos.

Una estructura de datos no se escoge por gusto: se escoge segun el tipo de acceso, busqueda, insercion, eliminacion, recorrido y relacion entre los datos.

Conceptos base

Dato

Valor almacenado y procesado por un programa: numeros, cadenas, fechas, objetos o registros completos.

Operacion

Accion sobre los datos: insertar, eliminar, buscar, actualizar, ordenar o recorrer.

Complejidad

Medida aproximada del costo temporal o espacial de un algoritmo cuando crece el tamano de entrada.

Complejidad algoritimica

O(1)

Tiempo constante. Ejemplo: consultar el frente de una cola conceptual.

O(log n)

Reduce el problema por mitades. Ejemplo: busqueda en arbol balanceado.

O(n)

Recorre todos los elementos. Ejemplo: cancelar un turno que puede estar en cualquier posicion.

O(n log n)

Comun en ordenamientos eficientes y consultas ordenadas.

O(n^2)

Comparaciones dobles. Debe evitarse con muchos datos.

Espacial

Memoria adicional usada por la estructura o algoritmo.

Aplicacion al proyecto

1. Problema

La oficina necesita atender estudiantes por orden de llegada y conservar evidencia de cada turno.

2. Estructura

Se eligio una cola FIFO porque representa naturalmente el flujo de atencion.

3. Implementacion

Spring Boot expone endpoints REST y MySQL conserva usuarios, turnos y estados.

4. Evaluacion

Se prueban enqueue, peek, dequeue, cancelacion, estados y casos limite.

Conclusion: La cola resuelve el problema principal con bajo costo operativo y una logica facil de sustentar. Si el sistema creciera, se podrian agregar tabla hash para busquedas por codigo, arbol AVL para ordenamientos avanzados y grafos para rutas de atencion entre dependencias.

Pseudocodigo de la cola

encolar(usuario):
    si usuario tiene turno activo:
        rechazar solicitud
    turno = crear turno PENDIENTE
    insertar turno al final

llamarSiguiente():
    si cola esta vacia:
        informar error
    turno = obtener frente
    turno.estado = EN_ATENCION
    guardar cambio

completar(turno):
    si turno.estado != EN_ATENCION:
        informar error
    turno.estado = ATENDIDO
